# ბმა „ალპიკი“ — მესაკუთრეთა თანხმობის სისტემა (v2)

ვებსისტემა, რომელშიც ამხანაგობის თითოეული მესაკუთრე შედის საკუთარი პირადი ნომრითა და წვდომის კოდით, ხედავს მხოლოდ საკუთარ ფართებს და ელექტრონულად აწერს ხელს დოკუმენტს. მთავარი ადმინისტრატორი ხედავს და მართავს მთელ ბაზას. ინტერფეისი მუშაობს ქართულ, ინგლისურ და რუსულ ენებზე.

> დავალებაში ნახსენები „თანამშრომელი“ ამ სისტემაში არის **ამხანაგობის წევრი (მესაკუთრე)**, „ჩანაწერი/დოკუმენტი“ კი არის **ფართი** და **ხელმოსაწერი წერილების პაკეტი**.

## 2. არქიტექტურა

```
ბრაუზერი (public/)                         სერვერი (src/)                          ბაზა (data/alpiki.db)
┌───────────────────────┐   HTTPS + cookie   ┌──────────────────────────────┐        ┌──────────────────────┐
│ index.html            │ ─────────────────▶ │ app.js — მარშრუტები, უფლებები│ ─────▶ │ persons, identifiers │
│ app.js  (SPA, hash-   │   JSON API         │ security.js — scrypt, ტოკენი, │        │ units, unit_owners   │
│         routing)      │ ◀───────────────── │   rate-limit, PNG შემოწმება   │ ◀───── │ documents            │
│ i18n.js (KA/EN/RU)    │                    │ db.js — მიგრაციები            │        │ signatures           │
│ styles.css            │                    │ seed.js — რეესტრის იმპორტი    │        │ sessions, audit_log  │
└───────────────────────┘                    └──────────────────────────────┘        └──────────────────────┘
```

* **დამოკიდებულებები: არცერთი.** გამოყენებულია მხოლოდ Node.js-ის ჩაშენებული მოდულები (`node:http`, `node:sqlite`, `node:crypto`). ეს ამცირებს თავდასხმის ზედაპირს და განახლების საჭიროებას. საჭიროა Node.js **22.13 ან უფრო ახალი**.
* **ბაზა:** SQLite (WAL რეჟიმი). სქემა იქმნება და ახლდება მიგრაციებით (`schema_version`); ახალი ვერსია მონაცემებს არ შლის.

## 3. უსაფრთხოება

* **ორი ფაქტორი შესვლისთვის:** პირადი ნომერი იდენტიფიკაციისთვის + 8-სიმბოლოიანი წვდომის კოდი, რომელსაც ადმინისტრატორი გასცემს. კოდი ბაზაში ინახება მხოლოდ **scrypt** ჰეშად და ეკრანზე ჩანს მხოლოდ ერთხელ.
* **შეცდომა არ ამჟღავნებს**, არსებობს თუ არა ნომერი ბაზაში (ერთნაირი პასუხი და დრო).
* **დაბლოკვა:** 5 არასწორი კოდის შემდეგ ანგარიში 15 წუთით იბლოკება; ასევე მოქმედებს შეზღუდვა IP მისამართზე.
* **სესია:** შემთხვევითი 256-ბიტიანი ტოკენი, `HttpOnly`, `SameSite=Strict`, production-ში `Secure`; ბაზაში მხოლოდ ჰეშია. კოდის განახლება ან გაუქმება წევრის ყველა სესიას ხურავს.
* **CSRF:** ცვლილების ყველა მოთხოვნას სჭირდება `X-Alpiki` სათაური და იგივე Origin.
* **სათაურები:** მკაცრი Content-Security-Policy (inline სკრიპტებისა და სტილების გარეშე), `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy: no-referrer`, HSTS.
* **ხელმოწერის შემოწმება სერვერზე:** მხოლოდ ნამდვილი PNG, ზომის ლიმიტით; თანხმობა სავალდებულოა; ფართი უნდა ეკუთვნოდეს ხელმომწერს; დუბლიკატს ბლოკავს როგორც კოდი, ისე ბაზის უნიკალური ინდექსი.
* **როლი:** `superadmin` ენიჭება მხოლოდ სერვერზე გაშვებული ბრძანებით. ვებგვერდიდან ან API-დან როლის შეცვლის მცდელობა უარყოფილია და აღირიცხება.
* **CSV ექსპორტი** დაცულია ფორმულის ინექციისგან (Excel).

## 4. გაშვება

### ლოკალურად
```bash
node --version                 # 22.13+
npm start                      # http://localhost:3000 — ბაზა და იმპორტი ავტომატურად
npm run create-admin -- --id 01020003679   # თავმჯდომარეს ანიჭებს Super Admin როლს და ბეჭდავს კოდს
```

### სერვერზე (production)
1. ნებისმიერი ჰოსტინგი, სადაც Node.js 22+ მუშაობს და ფაილი მუდმივად ინახება (VPS, Render/Railway მუდმივი დისკით, Hetzner და სხვ.).
2. დააყენეთ ცვლადები `.env.example`-ის მიხედვით: `NODE_ENV=production`, `DB_PATH` (მუდმივ დისკზე), `SECURE_COOKIES=1`, `TRUST_PROXY=1`, თუ nginx-ის ან ჰოსტინგის proxy-ის უკან მუშაობს.
3. **აუცილებლად HTTPS** (მაგ. nginx + Let's Encrypt).
4. `npm start`, შემდეგ სერვერზე ერთხელ: `npm run create-admin -- --id <თავმჯდომარის პირადი ნომერი>`.
5. **სარეზერვო ასლი:** ყოველდღე დააკოპირეთ `DB_PATH` ფაილი, მაგ. `sqlite3 alpiki.db ".backup backup-$(date +%F).db"`.

### სამუშაო პროცესი
1. ადმინისტრატორი შედის, „მესაკუთრეები“ → ირჩევს პირს → **„კოდის გაცემა“** → „შეტყობინების კოპირება“ → უგზავნის WhatsApp-ით.
2. მესაკუთრე შედის ნომრით და კოდით, კითხულობს დოკუმენტს, მონიშნავს ფართებს და აწერს ხელს. სისტემა ადასტურებს შენახვას.
3. ადმინისტრატორი „მიმოხილვაში“ ხედავს პროგრესს ფართებით და ფართის წილით, ფილტრავს ხელმოწერილს და ხელმოუწერელს და ტვირთავს CSV-ს.
